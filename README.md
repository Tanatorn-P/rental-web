หมายเหตุ ก่อนเริ่มงานให้ทุกคนติดตั้ง **GitHub Desktop** จาก https://desktop.github.com/download/ และ Login ให้เรียบร้อยก่อน

---

## 1. การเตรียมเครื่องและการ Setup ครั้งแรกสุด (ทำครั้งเดียว)

### ขั้นตอนที่ 1: Clone โปรเจกต์ผ่าน GitHub Desktop

1. เปิดโปรแกรม **GitHub Desktop** บนเครื่องคอมพิวเตอร์
2. ไปที่เมนู **File** -> **Clone repository...**
3. เลือกแท็บ **GitHub.com** หาชื่อโปรเจกต์ `rental-web` (หรือวาง URL ของ Repository)
4. **จุดสำคัญ (Local Path):** กำหนดเส้นทางเก็บไฟล์ในเครื่องให้อยู่ในโฟลเดอร์ของ Herd
* **Windows:** `C:\Users\<ชื่อยูสเซอร์ของคุณ>\Herd\rental-web`
* **macOS:** `/Users/<ชื่อยูสเซอร์ของคุณ>/Herd/rental-web`


5. กดปุ่ม **Clone**

---

### ขั้นตอนที่ 2: เชื่อมต่อกับ Laravel Herd

1. เปิดโปรแกรม **Laravel Herd** ขึ้นมา
2. ตรวจสอบในหน้าต่าง Sites จะพบว่ามีเว็บ `rental-web` ปรากฏขึ้นอัตโนมัติ
3. ทดลองเปิดเบราว์เซอร์ไปที่ `[http://rental-web.test](http://rental-web.test)` (หากยังขึ้น Error หน้าว่าง ถือเป็นเรื่องปกติเพราะยังไม่ได้สร้างไฟล์ `.env` และรัน Migration)

---

### ขั้นตอนที่ 3: Setup โปรเจกต์ใน VS Code หลัง Clone

1. เปิดโปรแกรม **VS Code** ไปที่เมนู **File** -> **Open Folder...** แล้วเลือกโฟลเดอร์ `rental-web`
2. เปิด Terminal ใน VS Code โดยกดปุ่ม `Ctrl + ~` (หรือ `Cmd + ~` บน Mac)
3. ป้อนคำสั่งตามลำดับดังนี้ (ทำทีละบรรทัด):

```bash
# 1. คัดลอกไฟล์ตั้งค่าระบบ
cp .env.example .env

# 2. ติดตั้งแพ็กเกจ PHP
composer install

# 3. ติดตั้งแพ็กเกจ Frontend (JavaScript/CSS)
npm install

# 4. สร้างคีย์ประจำโปรเจกต์
php artisan key:generate

# 5. สร้างไฟล์ Database เปล่า
# สำหรับ Windows (PowerShell):
New-Item -ItemType File -Path database/database.sqlite
# สำหรับ Mac / Linux:
touch database/database.sqlite

# 6. สร้างตารางทั้งหมดลง Database
php artisan migrate

# 7. คอมไพล์ไฟล์ CSS/JS สำหรับใช้งาน
npm run dev

```

*(ปล่อยให้คำสั่ง `npm run dev` ทำงานค้างไว้ใน Terminal ขณะเขียนโค้ด เพื่อให้หน้าเว็บอัปเดตสไตล์อัตโนมัติ)*

## 2. การจัดการ Branch (กิ่งการทำงานของโค้ด)

ในการทำงานร่วมกัน **เราจะไม่เขียนโค้ดลงบนกิ่งหลัก (`main`) โดยตรง** แต่จะสร้างกิ่งแยกส่วนตัวออกไปทำงาน เมื่อเสร็จแล้วค่อยนำมารวมกัน

### วิธีสร้าง Branch ใน GitHub Desktop

1. ตรงแถบด้านบน เลือก **Current Branch**
2. กดปุ่ม **New Branch**
3. พิมพ์ชื่อ Branch ตามหลักการตั้งชื่อ แล้วกด **Create Branch**
4. กดปุ่ม **Publish branch** เพื่อส่งกิ่งนี้ขึ้นสู่ระบบออนไลน์

### หลักการตั้งชื่อ Branch

ควรใช้ภาษาอังกฤษตัวพิมพ์เล็ก คั่นด้วยเครื่องหมายขีดกลาง (`-`) และระบุประเภทงานไว้ด้านหน้า:

* งานฟีเจอร์ใหม่: `feature/ชื่อฟังก์ชัน` เช่น `feature/customer-login`, `feature/admin-dashboard`
* งานแก้ไข/ปรับแต่ง: `fix/จุดที่แก้` เช่น `fix/navbar-style`, `fix/order-status-bug`

### การพิจารณาว่าเมื่อไหร่ควรสร้าง Branch ใหม่ vs ใช้ Branch เดิม

| สถานการณ์ | การตัดสินใจ |
| --- | --- |
| เริ่มทำฟีเจอร์ใหม่ / หน้าจอใหม่ (เช่น ทำหน้า Login, ทำหน้าเพิ่มสินค้า) | **สร้าง Branch ใหม่** |
| แก้ไข Bug หรือปรับแต่ง UI ของงานเดิมที่เคยทำไว้แล้ว | **ใช้ Branch เดิม** |
| งานเดิมทำเสร็จและส่งรวมเข้า `main` เรียบร้อยแล้ว แล้วต้องเริ่มงานชิ้นใหม่ | **สร้าง Branch ใหม่** (โดยตัดกิ่งมาจาก `main` ล่าสุด) |

## 3. ขั้นตอนการทำงานประจำวัน (ทำทุกครั้งก่อนและหลังเขียนโค้ด)

### ขั้นตอนก่อนเริ่มเขียนโค้ด

1. เปิด **GitHub Desktop**
2. สลับ Branch ไปที่ `main` แล้วกดปุ่ม **Fetch origin** (หรือ **Pull origin**) เพื่อดึงโค้ดล่าสุดที่เพื่อนคนอื่นทำเสร็จแล้วลงมาที่เครื่อง
3. สลับกลับมาที่ **Branch ของตนเอง**
4. กดปุ่ม **Choose a branch to merge into...** แล้วเลือก `main` เพื่ออัปเดตให้ Branch ของเราได้โค้ดล่าสุดของเพื่อนๆ มาด้วย
5. เปิด **VS Code** และเริ่มเขียนโค้ด

---

### ขั้นตอนเมื่อเขียนโค้ดเสร็จในแต่ละส่วน (Commit & Push)

เมื่อเขียนโค้ดหรือปรับหน้าจอเสร็จ 1 ส่วนย่อย ไม่ต้องรอให้เสร็จทั้งหมดทั้งวัน ให้ทำตามนี้:

1. สลับมาที่โปรแกรม **GitHub Desktop**
2. ด้านซ้ายมือจะแสดงรายการไฟล์ที่มีการแก้ไข (ติ๊กเลือกไฟล์ที่ต้องการบันทึก)
3. ในช่อง **Summary** (มุมซ้ายล่าง) ให้พิมพ์อธิบายสั้นๆ ว่าทำอะไรไป เช่น:
* `Add login form layout`
* `Fix button color on product list`


4. กดปุ่ม **Commit to [ชื่อ branch ของคุณ]**
5. กดปุ่ม **Push origin** ที่แถบด้านบน เพื่ออัปเดตโค้ดขึ้น GitHub

---

## 4. การส่งงานเข้าส่วนกลาง (Pull Request)

เมื่อทำฟีเจอร์ใน Branch ของตนเองเสร็จสมบูรณ์ และทดสอบผ่านหน้าเว็บ `[http://rental-web.test](http://rental-web.test)` แล้วว่าใช้งานได้ปกติ ไม่มี Error:

1. ใน **GitHub Desktop** กดปุ่ม **Create Pull Request** (โปรแกรมจะเปิดหน้าเว็บ GitHub ขึ้นมา)
2. ตรวจสอบว่ากำลังขอรวมโค้ดจาก Branch ของคุณ ไปยัง Branch `main`
3. เขียนรายละเอียดงานสั้นๆ แล้วกด **Create pull request**
4. แจ้ง **Admin/Maintainer** ให้เข้ามาตรวจสอบโค้ดและกด **Merge pull request** เพื่อรวมงานเข้าสู่ระบบหลัก

---

## 5. ข้อควรระวังและกฎเหล็กที่ห้ามทำ
❌ **ห้ามเขียนโค้ดลงใน Branch `main` โดยตรง**<br>
ตรวจสอบใน GitHub Desktop ทุกครั้งก่อนเริ่มเขียนโค้ดว่า ตัวเองอยู่ที่ Branch งานของตนเอง ไม่ใช่ `main`

❌ **ห้าม Push ไฟล์ `.env` หรือ `database.sqlite` ขึ้น GitHub**<br>
ไฟล์เหล่านี้เป็นข้อมูลการตั้งค่าประจำเครื่องและฐานข้อมูลทดสอบส่วนตัว ในไฟล์ `.gitignore` จะทำการบล็อกไว้ให้อยู่แล้ว ห้ามไปปลดล็อกหรือสั่งนำเข้าไฟล์เหล่านี้เด็ดขาด

❌ **ห้ามดองงานไว้เยอะๆ แล้วค่อย Commit ทีเดียว**<br>
ควรกด Commit ย่อยๆ บ่อยๆ (เช่น ทำเสร็จ 1 ปุ่ม หรือ 1 ฟอร์ม ก็ Commit ได้เลย) เพื่อให้ง่ายต่อการย้อนกลับไปแก้ไขหากเกิดข้อผิดพลาด

⚠️ **เมื่อเจอคำว่า "Merge Conflict" (โค้ดชนกัน) อย่าตกใจ**<br>
เกิดขึ้นเมื่อมีคนแก้ไขไฟล์เดียวกันและบรรทัดเดียวกันพร้อมกัน หากหน้าจอขึ้นแจ้งเตือน ให้หยุดทำรายการ แล้วแจ้งเพื่อนในทีม เพื่อช่วยเปิดดูใน VS Code และเลือกโค้ดส่วนที่ถูกต้องร่วมกัน

💬 **การสื่อสารสำคัญที่สุด**<br>
ก่อนเริ่มทำฟังก์ชันใดๆ ให้พิมพ์แชตกลุ่มเสมอว่า *กำลังจะทำอะไร ที่หน้าไหน* เพื่อนในกลุ่ม จะได้หลีกเลี่ยงการแก้ไขไฟล์เดียวกันในเวลาเดียวกัน

รวมคำศัพท์ Git & GitHub ที่สำคัญสำหรับการทำงานร่วมกันในทีม
### 1. พื้นที่เก็บงานและการเริ่มต้น (Repository & Setup)

* **Repository (Repo)**: คลังเก็บไฟล์โปรเจกต์ทั้งหมด (เปรียบเหมือนโฟลเดอร์หลักของโปรเจกต์) มีทั้งบนเครื่องเรา (**Local Repo**) และบนเว็บ (**Remote Repo**)
* **Clone**: การดาวน์โหลดคลังโปรเจกต์จาก GitHub บนออนไลน์ ลงมาไว้ในเครื่องของเราเป็นครั้งแรก
* **Fork**: การก๊อปปี้ Repository ของคนอื่นมาเป็น Repository ของเราเองบน GitHub (นิยมใช้เวลาอยากนำโปรเจกต์ผู้อื่นมาพัฒนาต่อเอง)

### 2. การทำงานและการบันทึกโค้ด (Working & Saving)

* **Changes / Working Directory**: ไฟล์ในเครื่องที่มีการแก้ไข เพิ่ม หรือลบ แต่ยังไม่ได้ทำการบันทึกประวัติ
* **Commit**: การบันทึกประวัติการแก้ไขโค้ด ณ ช่วงเวลานั้น (เปรียบเหมือนการกด **Save Point** ในเกม) ควรพิมพ์ข้อความอธิบายด้วยว่าแคปชั่นนี้แก้/ทำอะไรไป
* **Branch**: กิ่งการทำงานการแยกพื้นที่เขียนโค้ดออกจากกัน เพื่อให้เราลองแก้โค้ดหรือทำฟีเจอร์ใหม่ได้โดยไม่กระทบโค้ดหลักของคนอื่น
* **Main (หรือ Master)**: Branch หลักของโปรเจกต์ เป็นพื้นที่เก็บโค้ดส่วนกลางที่ทดสอบแล้วว่าใช้งานได้จริง สมบูรณ์ และไม่มี Error

### 3. การส่งและดึงข้อมูลระหว่างเครื่องกับออนไลน์ (Syncing)

* **Push**: การส่ง Commit จากเครื่องเรา (Local) ขึ้นไปอัปเดตบน GitHub (Remote) เพื่อให้เพื่อนๆ มองเห็น
* **Fetch**: การสั่งให้ Git ไปเช็กบน GitHub ว่ามีเพื่อนคนไหน Push โค้ดใหม่ขึ้นไปบ้างหรือยัง (เช็กเฉยๆ ยังไม่ดึงไฟล์มาทับในเครื่อง)
* **Pull**: การดึงโค้ดล่าสุดจากบน GitHub ลงมาอัปเดตทับไฟล์ในเครื่องเราทันที (ค่าเท่ากับ Fetch + Merge)

### 4. การทำงานร่วมกันในทีม (Collaboration)

* **Merge**: การนำโค้ดจาก Branch หนึ่ง ไปรวมเข้ากับอีก Branch หนึ่ง (เช่น รวมกิ่งงานเรา เข้ากิ่ง `main`)
* **Pull Request (PR)**: การสร้าง "คำขอรวมโค้ด" บนเว็บ GitHub เพื่อแจ้งเพื่อนในทีมว่า *"ฟีเจอร์นี้ทำเสร็จแล้ว ช่วยตรวจโค้ด (Code Review) แล้วกด Merge เข้า main ให้หน่อย"*
* **Merge Conflict (โค้ดชนกัน)**: เหตุการณ์ที่คน 2 คนแก้ไขไฟล์เดียวกัน ในบรรทัดเดียวกัน แล้วส่งงานขึ้นไปพร้อมกัน จน Git ไม่รู้ว่าจะใช้โค้ดของใคร ทำให้เราต้องมาเลือกด้วยตนเองว่าต้องการเก็บโค้ดของใครไว้

### สรุป ลำดับคำศัพท์ที่จะได้ใช้บ่อยที่สุดในทุกครั้ง<br>

 **Clone** (ทำวันแรก) ➔ **Branch** (แยกกิ่งงาน) ➔ **Commit** (เซฟงานย่อย) ➔ **Push** (ส่งขึ้นเว็บ) ➔ **Pull Request** (ขอรวมเข้า main) ➔ **Pull** (เพื่อนดึงโค้ดเราไปใช้)
